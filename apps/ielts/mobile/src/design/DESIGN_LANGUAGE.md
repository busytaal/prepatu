# Prepatu — Voice Design Language

> A mobile-only design system for voice-first interaction.  
> Platform: React Native (Expo)  
> Tokens file: `mobile/src/design/tokens.ts`

---

## 1. Core Concept — The Orb as Relationship Signal

The **orb is the soul of every screen**. It never just shows a state — it signals a *relationship contract* between the user and the agent.

| Orb Position | Mode | Message |
|---|---|---|
| **Bottom-right corner** (large) | Home / idle | "Tap me to begin" |
| **Right edge, mid-height** (small) | Assistant active | "I am at your service" |
| **Screen centre** (medium) | Interview active | "You answer to me" |

The physical position of the orb tells the user who is in control **without a single word**. Designers must never place the orb in the centre during assistant mode, or on the side during interview mode.

## 2. Screen Anatomy

### 2a. Home Screen

```
┌────────────────────────────┐
│  prepatu                   │  ← wordmark, top-left, 28pt bold
│  tap to speak              │  ← hint, 12pt, muted
│                            │
│                            │
│                            │
│                            │
│                     ╭────╮ │
│                     │ orb│ │  ← corner orb, 130×130, bottom-right
│                     ╰────╯ │
└────────────────────────────┘
```

- No transcript. No controls. Nothing else.
- One action: tap the orb.

---

### 2b. Assistant Screen (voice navigation assistant)

Orb is **side-anchored** once connected — it slides to the right edge at mid-screen height.

```
┌────────────────────────────┐
│  prepatu                   │  ← wordmark, stays visible
│                            │
│  ┌──────────────────────┐  │
│  │   Intent text        │  │  ← 32pt light, centred block, left of orb width
│  │   (LLM label)        │  │     e.g. "Navigation"
│  │                      │  │
│  │   raw transcript     │  │  ← 14pt, muted grey below intent
│  └──────────────────────┘  │
│                            │
│  [ Action ]  [ Action ]    │  ← artifact action pills, scrollable row
│                            │
│                       [◉]  │  ← side orb, 56px, right edge mid-height
│                            │
│  [🎤]              [🔇]    │  ← mute controls, bottom bar
└────────────────────────────┘
```

**Key rule**: when the orb is on the side, the text content area owns the full width minus a right-margin equal to `orbSidePadding`. The user's attention should be on the content, not the orb.

---

### 2c. Interview Screen (IELTS examiner)

Orb is **centred** — it owns the visual focal point. The user answers *to* the orb.

```
┌────────────────────────────┐
│  [Part 1]          03:42   │  ← interview badge (left) + timer (right)
│                            │
│  Intent text               │  ← 32pt light, centred
│  (LLM label)               │     e.g. "Question"
│                            │
│  raw transcript            │  ← 14pt, muted, centred, max 2 lines
│                            │
│                            │
│          ╭──────╮          │
│          │  orb │          │  ← centred orb, 72px + glow ring
│          ╰──────╯          │
│                            │
│  [ Yes ]  [ No ]  [ Skip ] │  ← artifact action pills, centred row
│                            │
│  [🎤]              [🔇]    │  ← mute controls, bottom bar
└────────────────────────────┘
```

**Key rule**: the timer and badge at the top are always visible during an interview session. They remind the user this is a timed, formal test context.

## 3. The Intent Text System

The Intent Text is **the most important piece of content on the screen**. It is not a transcript — it is a *moment label* generated by the LLM.

### What is Intent Text?

When the agent says *"Hello, how are you today?"*, the intent is `"Greeting"`.  
When the agent asks *"Can you tell me about your hometown?"*, the intent is `"Question"`.  
When the user says *"Hello"*, the intent is simply `"Hello"`.

The goal is **glanceability** — the user should understand the conversational moment in under 300ms without reading a sentence.

### Display Rules

| Property | Value |
|---|---|
| Font size | 32pt |
| Weight | 300 (light) — approx, not bold |
| Alignment | Centre (interview) / left-aligned (assistant) |
| Max length | ~20 characters |
| Animation | Fade in/out on change (250ms) |
| Position | Upper content area, clear of the orb |

### Transcript Rules (secondary)

| Property | Value |
|---|---|
| Font size | 14pt |
| Weight | 400 |
| Color | `#6B6B80` (low-contrast, intentionally) |
| Max lines | 2 (truncate with ellipsis) |
| Placement | Directly below Intent Text, 10pt gap |
| Purpose | Confirmation / accessibility, not primary reading |

## 4. Listening State Communication

The user must *always* know when the mic is live. We use a three-layer system:

### Layer 1 — Orb colour
`listening` state → orb turns `#3ECF6A` (green). This is the first and clearest signal.

### Layer 2 — Listening ring
A thin dashed arc ring rotates around the orb when the system is actively capturing voice input. This is distinct from the glow used in `speaking` state.

| Property | Value |
|---|---|
| Stroke width | 1.5px |
| Colour | `#3ECF6A` |
| Gap from orb edge | 6px |
| Dash pattern | `[6, 4]` |
| Rotation duration | 2800ms (slow, ambient) |
| Opacity | 0.7 max |

The ring is visible **only** in `listening` state. It disappears immediately when the user starts speaking (VAD triggers) or when the agent takes over.

### Layer 3 — Status hint text
Below the orb, a small uppercase label: `LISTENING`, `SPEAKING`, `CONNECTING…`  
Font: 11pt, letter-spacing 2, all-caps, `#444458` (barely visible — for confirmation, not attention).

## 5. Mute Controls

Mute lives in a **fixed control bar** at the very bottom of every active voice screen (assistant + interview). It is always visible during a session.

### Two controls

| Button | Icon | Label | Muted State |
|---|---|---|---|
| Mic mute | microphone icon | (none) | Icon tinted `#E8A020`, subtle amber bg |
| Speaker mute | speaker icon | (none) | Icon tinted `#E8A020`, subtle amber bg |

### Voiceless Mode
When **both** mic and speaker are muted simultaneously, the screen enters **voiceless mode**:
- Orb dims to `mutedMic` grey but stays visible
- The intent text area shows the last known intent with reduced opacity (0.5)
- Artifact action buttons remain fully interactive
- The LLM is still connected — tapping action buttons sends messages
- A subtle pill at the top of the control bar reads: `"voiceless — tap actions to continue"` in `#E8A020`

This allows the user to continue the session silently using only button interactions, which is critical for private environments (commute, office).

## 6. Artifact Action Buttons

These are contextual prompts from the LLM rendered as tappable pills below the intent text (assistant mode) or below the orb (interview mode).

### Anatomy of an action pill

```
┌─────────────────────────┐
│         Label           │
└─────────────────────────┘
Background: #1E1E30
Border: 1px solid #2E2E44
Label: 14pt, #C0C0D8
Border-radius: 999 (fully rounded pill)
Min-width: 80px, padding: 10px 18px
```

### Behaviour
- Horizontal scrollable row, max 3 visible at once before scroll
- Press state: background lifts to `#2A2A3E`, no scale change (keeps it calm)
- Dismiss on tap — the action is sent to the LLM as a text response
- One special action is always last (if present): **End Session** — uses danger colours (`#2A1A1A` bg, `#E74C3C` text)

## 8. Navigation Model

Navigation is intentionally hidden on active voice screens. The user should not see a tab bar or back button while speaking — it breaks the immersive voice context.

### Navigation rules
- **No visible nav bar / tab bar** on AssistantScreen or InterviewScreen
- Back navigation is done by the agent verbally (asks "shall I take you back?") or via an artifact action button ("← Go Back" pill)
- `HomeScreen` has no nav bar either — single tap interaction only
- System gestures (swipe-back on iOS) remain available as an escape hatch but are not advertised

---

## 9. Motion Principles

All animations should feel **ambient and breathing**, not mechanical.

| Principle | Rule |
|---|---|
| Slowness = calm | Listening breathe: 1600ms/half-cycle. Never fast idle animations. |
| Speed = urgency | Speaking pulse: 380ms. Should feel slightly urgent — the agent is talking. |
| Orb entrance | Spring physics, not linear. `tension: 60, friction: 10`. |
| Text transitions | Cross-fade only. No slide. Intent text fades in 250ms. |
| No bounce on mute | Mute button press: 120ms scale-down, no spring back. Mute is a deliberate act. |
| Glow, not shadow | All depth is expressed through glow (`rgba` behind the orb), never hard drop-shadows. |

## 12. Bottom-Arc Orb

The **bottom-arc** is a new orb position designed for screens where voice is ambient and helpful rather than central (Home, History, Profile).

### Shape
A semi-circle (the top half of the orb circle) whose flat edge is flush with the very bottom of the screen. It protrudes upward — the dome faces the content. Width = 120px. Visible height = 60px.

```
          ╭──────────────╮
         ╱                ╲
─────────────────────────────────  ← screen bottom edge
```

### Rationale
- Takes 60px of vertical space vs 72–130px for a full circle.
- Glow halo bleeds upward into the screen; the flat base is invisible, merging with the background.
- Tapping the arc toggles voice off (same as "no voice assistance" label beneath it).

### "No voice assistance" label
A small `12pt` muted text link below/over the arc. Always present when voice is active. Tapping it disconnects the voice session and replaces the arc with a quiet `VOICE OFF` badge. There is no way to re-enable voice within the screen (requires navigation back to Home).

## 13. Form Design — Friendly & Voice-First

Forms in prepatu are not web forms. They feel **conversational**, not bureaucratic.

### Guiding principles

| Principle | Implementation |
|---|---|
| Warm labels | ALLCAPS micro-label, 12pt, muted. Never bold headers. |
| Breathing inputs | Rounded 14px corners. Slightly larger touch target (15px v-padding). |
| Voice fills in | When the LLM fills a field, a green glow flashes briefly — a moment of delight, not a notification. |
| Error gentleness | Error message reads *"Required — say it or type it"*, not *"This field is required"*. |
| One CTA | A single rounded-16 green `Continue` button. No cancel, no back, no reset. |

### Field anatomy

```
  NAME *
 ┌───────────────────────────────────┐  ← borderRadius 14, background elevated
 │  Alex                             │     Normal: border rgba(255,255,255,0.06)
 └───────────────────────────────────┘     Error:  border #E74C3C
                                            Flash:  bg rgba(62,207,106,0.18) + border #3ECF6A
```

### LLM field-update flash animation
When the server fills a field via a `field_update` artifact:
1. The `Animated.View` border colour interpolates from default → `#3ECF6A` over **200ms**.
2. The background tints to `rgba(62,207,106,0.18)`.
3. Both fade back to default over **800ms**.
4. Net effect: a gentle green pulse. The user sees "the voice understood me".

Token reference: `colors.fieldUpdate.glow`, `colors.fieldUpdate.border`.

### Form layout hierarchy

```
Tell us about yourself        ← 24pt, weight 600
Say your answers or type      ← 14pt, weight 300, secondary

  NAME *
  ┌──────────────────────────┐
  └──────────────────────────┘

  DATE OF BIRTH *
  ┌──────────────────────────┐
  └──────────────────────────┘

  ┌──────────── Continue ────────────┐
  └──────────────────────────────────┘   ← green, borderRadius 16
```

## 14. Voice Dismissal Pattern

Every screen that has a persistent voice session must offer a clear, always-visible way to dismiss voice assistance. This is a first-class design element, not an afterthought.

### Components

1. **The orb itself is tappable** — pressing the bottom-arc orb disconnects voice.
2. **"no voice assistance" label** — `12pt`, muted colour (`#444458`), centered below the orb. Always rendered when voice is active.
3. **Voice-off badge** — after dismissal, a small `VOICE OFF` chip replaces the orb area. This gives the user confirmation that voice is truly off.

### Placement rules
- On bottom-arc screens: label sits inside the safe-area padding below the arc.
- Never put the label behind a modal or behind the keyboard.
- The label's hit-slop is `{ top: 8, bottom: 8, left: 16, right: 16 }` — comfortable thumb tap.

### No re-enable in-screen
Once voice is dismissed on a secondary screen (History, Profile), it stays off for that screen session. The user returns to Home if they want voice back. This prevents accidental re-connections and is a deliberate, calm UX choice.

---

- Minimum contrast for transcript text (`#6B6B80` on `#0A0A14`) = 3.8:1 — passes WCAG AA for large text only. This is intentional — transcript is decorative/secondary.
- Intent text (`#FFFFFF` on `#0A0A14`) = 21:1 — passes WCAG AAA.
- All mute buttons must have `accessibilityLabel` and `accessibilityRole="button"`.
- `accessibilityLiveRegion="polite"` on intent text area so screen readers announce changes.
- Voiceless mode must remain fully operable for users who cannot use audio at all.
